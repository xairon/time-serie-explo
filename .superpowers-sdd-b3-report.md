# Task B3 — Vue Comparaison — Report

## Scope

Implemented Task B3 of `docs/plans/2026-07-07-module-climat-lot2.md`: the
"Comparaison" section of the Climat module's Point panel. Purely a frontend task —
the backend endpoints it needs (`GET /observatory/climat/compare-years` and
`GET /observatory/climat/grid-indices`) already exist and were delivered in Task A1
(`api/routers/observatory_climat.py`); no backend changes were required or made.

## What was built

### Backend (unchanged, verified as sufficient)
- `compare-years?lat&lon&years=` returns, per requested year: `cumul_mensuel`
  (monthly running rainfall sum + `cumul_normal`) and `spi_3` (3-month SPI series).
- `grid-indices?month=YYYY-MM&window=&index=spi` returns per-cell SPI with a
  server-computed `index_class` (McKee 7-class) — reused as-is for the mini-maps
  colour, no client-side re-classification.

### Frontend
- **Types** (`lib/observatory-types.ts`): `ClimatCompareYears`,
  `ClimatCompareYearData`, `ClimatCompareMonthCumul`, `ClimatCompareMonthSpi`.
- **API client** (`lib/observatory-api.ts`): `climat.compareYears(lat, lon, years)`.
- **Pure helpers** (fully unit-tested, no React/DOM):
  - `lib/climat-year-select.ts` — `MIN_COMPARE_YEARS`/`MAX_COMPARE_YEARS` (2-6),
    `DROUGHT_YEAR_PRESETS` (1976/1989/2003/2022), `defaultCompareYears(currentYear)`
    (presets + current year), `toggleYear` (add/remove respecting bounds, no-op
    same-reference return when a move would violate them), `isValidYearSelection`.
  - `lib/climat-compare.ts` — `buildCumulSeries`/`buildNormalSeries`: shape the
    `compare-years` response into Plotly-ready per-year traces (x = calendar month
    1-12, missing months → `null` so lines break instead of dropping to 0) and a
    single reference "normale" trace picked from the selected year with the most
    complete monthly coverage.
  - `lib/climat-minimap.ts` — `projectCellToPixelRect`: flat equirectangular
    lat/lon → canvas-pixel-rect projection over a fixed France bbox, used by the
    mini-map canvas renderer (see below).
- **Hooks** (`hooks/useClimat.ts`):
  - `useClimatCompareYears(lat, lon, years)` — gated on lat/lon defined AND
    `years.length >= MIN_COMPARE_YEARS`; query key includes a sorted year string so
    TanStack Query caches per exact year set.
  - `useClimatCompareGridIndices(years, calendarMonth, enabled)` — one
    `useQueries` entry per selected year, query key
    `['climat','grid-indices', 'YYYY-MM', 3, 'spi']` — **identical shape** to the
    Situation view's `useClimatGridIndices`, so a mini-map transparently reuses the
    Situation map's cache when they target the same month/window/index, and vice
    versa. Only the selected years are ever fetched.
- **Components** (`components/climat/`):
  - `YearMultiSelect.tsx` — preset chips (always visible, toggleable) + chips for
    any already-selected non-preset year + an "add year" `<select>` dropdown for
    anything else (1950→current year). A chip that would break the 2-6 bound is
    `disabled` rather than silently failing.
  - `CompareCumulChart.tsx` — Plotly, one line per selected year (distinct colour
    per year) + a dashed grey "normale" reference line, `hovermode: 'x unified'`
    with a hover template showing `year · month : cumul mm`, mirroring
    `PrecipNormalChart.tsx`'s dark styling conventions.
  - `MiniSpiMap.tsx` + `CompareSpiMiniMaps.tsx` — the small-multiples map row (see
    "Mini-maps approach" below) plus a single `<select>` month picker (default
    June, per the plan).
  - `CompareYearsSection.tsx` — composes the above into the "Comparaison" section,
    owns `years`/`month` state, wired into `PointPanel.tsx` right after the
    drought-episodes table (lightest integration: PointPanel already just stacks
    sections vertically, so Comparaison is a fourth stacked section, independent of
    the point-series load state since it hits its own endpoint).
- **i18n**: `climat.compare.*` (title, yearsLabel, yearsHint, addYear, cumulTitle,
  normal, miniMapsTitle, monthLabel) added to both `fr.json` and `en.json`.

## Mini-maps approach chosen (and why)

**Canvas, not MapLibre.** The plan flagged that 6 full MapLibre/WebGL instances for
a non-interactive ~180px thumbnail would likely be heavy, and offered a static
SVG/canvas render of the grid squares as the pragmatic alternative. I went with
**canvas**: `MiniSpiMap.tsx` projects each returned grid point (already filtered to
mainland France by the backend, not the full 11,496-cell superset) to a pixel rect
via the pure `projectCellToPixelRect` helper and does one `fillRect` per cell,
coloured directly from the server's `index_class` (no client-side McKee
re-classification). No pan/zoom/click handlers, fixed France bbox, ~180×180px.

This avoids: WebGL context churn/limits when rendering up to 6 mini-maps alongside
the already-open full ClimatMap on the Situation view underneath the panel; the
~1-2s per-instance MapLibre style/tile init that would blow the "<3s for 4 years"
budget; and unnecessary bundle/runtime coupling to MapLibre for a decorative
thumbnail. The fetch side (`useClimatCompareGridIndices`) issues all N year queries
in parallel via `useQueries`, and each render pass is a handful of `fillRect` calls
— comfortably sub-100ms per map, so the whole comparison view (data + render) loads
well inside the target even for 6 years.

Trade-off accepted: the mini-maps are visually simpler (no basemap/coastline
context, just coloured squares on a plain background) than the full ClimatMap —
consistent with "small multiples" conventions where the point is fast side-by-side
comparison, not cartographic detail.

## Concerns / follow-ups for later tasks

- The "add year" dropdown in `YearMultiSelect` offers every year from 1950 to the
  current year regardless of actual ERA5 grid coverage at the selected cell; a year
  with no data simply renders an empty/null-filled trace and an empty mini-map
  rather than being hidden — acceptable for now (no separate "available years"
  endpoint exists), but could be tightened once/if the range endpoint exposes a
  proper `min_date` at the point level (Task B2's `point-series` already returns
  the full history so this is derivable client-side if desired later).
- Mini-map canvases have no basemap/coastline for orientation (see trade-off
  above) — fine for expert users comparing colour patterns, but worth a "France
  outline" static overlay in a later polish pass (Task C3) if it reads as too bare.
- `CompareYearsSection` always renders (not collapsed/lazy) once the panel opens,
  issuing its own `compare-years` + N `grid-indices` calls immediately alongside
  the existing point-series/episodes calls. All are cached 24h both client- and
  server-side (Redis), so repeat opens are cheap, but the *first* open of a given
  cell now fires more concurrent requests than before B3 — not a problem observed
  in testing, but worth watching if it ever needs to become click-to-expand.
