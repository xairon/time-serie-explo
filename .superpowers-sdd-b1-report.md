### Page + components (`frontend/src/pages/ClimatPage.tsx`, `frontend/src/components/climat/*`)
- `ClimatPage.tsx` — orchestrates state (variable, window, month), wires the three new hooks,
  composes the map + banner + picker + stepper + legend. Month bounds are read from the existing
  `useERA5Range` hook (same ERA5 grid coverage as the Observatory overlay, so no new range
  endpoint was needed).
- `ClimatMap.tsx` — a **lean**, dedicated MapLibre map (not `ObservatoryMap`, which is heavily
  coupled to the station/zone/sensor overlay state — matches the plan's fallback instruction).
  Same base style (`voyager-gl-style`) and squares approach as the Observatory ERA5 overlay, but
  built around the Climat endpoints' generic response shape (`value` / `index_class` instead of
  per-field `ERA5GridPoint`). Click popup on a cell reuses the existing
  `observatory.era5.popupSpiLabel` / `popupStiLabel` i18n keys for SPI/STI (no duplicated wording).
- `VariablePicker.tsx` — 6-way variable radio group (SPI default, STI, bilan hydrique,
  précipitations, température, ETP) + a window selector (1/3/6/12) shown only for SPI/STI.
- `MonthStepper.tsx` — ‹ month › stepper; reuses the pure `addMonths`/`comparePeriods`/
  `formatPeriodLongFR` helpers already exported from `lib/meteo-timeline.ts` (generic 'YYYY-MM'
  arithmetic, unrelated to the disabled MétéEAU *page* — no MétéEAU code was touched).
- `ClimatLegend.tsx` — discrete 7-class McKee legend for SPI/STI (reuses
  `SPI_CLASS_COLORS`/`STI_CLASS_COLORS`/`*_CLASS_ORDER` from `era5-colors.ts`) or a gradient
  legend for the raw variables.
- `SituationBanner.tsx` — renders "X % du territoire en sécheresse (SPI < −1) · mois le plus sec
  depuis AAAA · zones les plus touchées : [chips]" fed by `/situation-summary`. All text-shaping
  logic (percentage rounding, lat/lon chip formatting, null-year handling) lives in the pure,
  independently-tested `lib/climat-situation-format.ts`.

### Lib additions
- `lib/climat-colors.ts` — `ClimatVariable` type + `CLIMAT_VARIABLES` config (gradients for the 4
  raw vars, hooks into the existing SPI/STI 7-class palette for the 2 index vars), color-expression
  builders, `climatFormatValue`.
- `lib/climat-grid.ts` — `climatMonthlyToSquares` / `climatIndicesToSquares`: GeoJSON square-polygon
  builders for the Climat endpoints' response shapes (mirrors `era5-grid.ts` but for `{value,
  mois_complet}` / `{spi|sti, index_class}` instead of the observatory's `ERA5GridPoint`).
- `lib/climat-situation-format.ts` — pure banner formatting helpers (`formatLatLon`,
  `formatDroughtPct`, `buildSituationBannerData`).
- `lib/observatory-types.ts` — added `ClimatMonthlyPoint`, `ClimatIndexPoint`,
  `ClimatSituationSummary` (typed against `api/routers/observatory_climat.py`'s actual response
  fields, e.g. `pct_secheresse` not `pct_drought`, `top5_cellules_seches`).
- `lib/observatory-api.ts` — new `climat.*` block: `gridMonthly`, `gridIndices`,
  `situationSummary`, next to the existing `era5.*` block.
- `hooks/useClimat.ts` — `useClimatGridMonthly`, `useClimatGridIndices`,
  `useClimatSituationSummary`. All gated with TanStack Query's `enabled` (only fire once a month
  is resolved / the page is mounted), 24h `staleTime` matching the backend's 24h Redis cache.

### i18n

## Fix: revue B1

Addressed two Important review findings on the Task B1 Climat Situation view (`feat/climat-module`).

**1. `ClimatMap.tsx` — map recreated on language change**
The map-init `useEffect` depended on `[t]`. react-i18next returns a new `t` reference on every
language change, so switching language destroyed and rebuilt the whole maplibre map (style reload,
viewport reset, tile cache lost). Fixed with the same ref pattern already used for
`variableRef`/`windowRef`: added `tRef` (kept current every render), the map-init effect now runs
once (`[]` deps, with an `eslint-disable-next-line react-hooks/exhaustive-deps` documenting why),
and the click-popup handler reads `tRef.current` at event time instead of closing over `t` — so
popups created after a language switch still pick up the new translations.

**2. `MonthStepper.tsx` — hardcoded French strings**
- aria-labels "Mois précédent"/"Mois suivant" routed through `t('climat.stepper.prevMonth'/'nextMonth')`,
  new keys added to both `frontend/src/i18n/locales/fr.json` and `en.json` under the existing
  `climat.*` nesting (fr: "Mois précédent"/"Mois suivant", en: "Previous month"/"Next month").
- Month label switched from `formatPeriodLongFR` (hardcoded French month names) to
  `Intl.DateTimeFormat(i18n.language, { month: 'long', year: 'numeric' })`, mirroring
  `ClimatLegend.tsx:52-55`'s pattern exactly (same regex parse of the 'YYYY-MM' string, same
  `new Date(year, month-1, 1)` construction).
- Added `frontend/src/components/climat/MonthStepper.test.tsx` (4 tests, following the
  `VariablePicker.test.tsx` style: `i18n.changeLanguage()` + RTL render/screen queries), including
  an explicit assertion that English rendering shows "Previous month"/"Next month" aria-labels and
  "June 2026" as the Intl-formatted month label.
