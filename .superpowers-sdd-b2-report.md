# Task B2 — Vue Point/Zone de la page Climat

**Branch**: `feat/climat-module`
**Plan**: `docs/plans/2026-07-07-module-climat-lot2.md` (Phase B, Task B2)

## What was built

### Cell click → deep-linkable Point panel
- `hooks/useClimat.ts` — new `useSelectedCellParam()` round-trips the selected cell through
  the `?lat&lon` URL query params (`react-router-dom`'s `useSearchParams`), same convention as
  `ObservatoryPage`'s existing lat/lon fly-to params but kept *live* in the URL instead of
  consumed once, so a shared link opens the panel already populated. Coordinates are stored
  with 2-decimal precision (`toFixed(2)`).
- `components/climat/ClimatMap.tsx` — the cell-click handler now calls `onCellClick(lat, lon)`
  instead of opening a MapLibre `Popup`; the panel carries far more information than a one-line
  popup ever could. The cell centre is computed as the clicked square's centroid (average of its
  4 corners), rounded back to the 0.1° grid. A second GeoJSON source/layer
  (`climat-selected-cell` / `-line`, cyan outline) highlights the currently-open cell — new pure
  helper `lib/climat-grid.ts::climatSelectedCellSquare(lat, lon)` builds that outline, unit-tested
  alongside the existing `climatMonthlyToSquares`/`climatIndicesToSquares`. The `window` prop was
  dropped from `ClimatMap` (it was only ever used by the removed popup's label).
- `pages/ClimatPage.tsx` — wires `useSelectedCellParam` to `ClimatMap` (`onCellClick`/`selectedCell`)
  and renders `<PointPanel>` when a cell is selected.

### `PointPanel.tsx` — the side panel itself
- Large panel (`w-full sm:w-[560px] lg:w-[680px]`), consistent with the repo's drawer pattern
  (`RightDrawer`/`StationDrawer`: `role="dialog"`, slide-in from the right, mobile scrim,
  sticky header with an X close button). Closable via the X button, backdrop click (mobile), or
  Escape key.
- Title "Analyse du point" + formatted coordinates ("47.40° N, 0.70° E").
- Composes `PrecipNormalChart`, `ClimatIndexChart`, `EpisodesTable`, and a direct CSV export
  link — all fed by two hooks: `useClimatPointSeries(lat, lon)` (full 1950→présent history) and
  `useClimatPointEpisodes(lat, lon)` (fixed 3-month "meteorological drought" window, matching the
  backend default — no window selector was added here per plan scope; the SPI/STI chart's window
  selector covers that need).
- Loading skeleton + error message (`isError`) states for both queries.

### Charts
- `PrecipNormalChart.tsx` — Plotly (`react-plotly.js`), same dark styling/conventions as
  `components/observatory/TimeseriesChart.tsx`: precipitation bars + a dotted normal line,
  `xaxis.rangeslider` for zoom/brush across the full 1950→présent domain, with the default
  visible range set to the last 10 years (plan requirement) via `xaxis.range`.
- `ClimatIndexChart.tsx` — Recharts `ComposedChart`, same conventions as
  `components/observatory/DroughtIndexChart.tsx` (7-class WMO `ReferenceArea` severity bands,
  zero `ReferenceLine`, coloured bars). Generalized to switch between SPI and STI (tabs) and
  window 1/3/6/12 (reuses `CLIMAT_WINDOWS`), classifying each point client-side via the existing
  `classifyIndex`/`SPI_CLASS_COLORS`/`STI_CLASS_COLORS` from `lib/era5-colors.ts` — no duplicated
  classification logic. Legend reuses the existing `observatory.spi.*`/`observatory.sti.*` i18n
  labels.
- Both charts are deliberately **not** unit-render-tested (no existing test in the repo renders
  a Plotly-based component; Recharts' `ResponsiveContainer` is likewise untested elsewhere under
  jsdom) — `PointPanel.test.tsx` mocks both as stub components and focuses on composition/behavior.

### Episodes table
- `lib/climat-episodes.ts` — pure helpers, unit-tested independently (mirrors the
  `climat-situation-format.ts` pattern): `sortEpisodes(episodes, key, direction)` (by `debut` or
  `duree_mois`, ties on duration always break ascending by start date) and
  `findCurrentEpisode(episodes, lastMonth, lastMonthSpi)` (the ongoing episode iff the last
  available month's SPI < −1 AND an episode's `fin` matches that month).
- `EpisodesTable.tsx` — début/fin/durée/SPI min/déficit columns, sortable headers (click
  toggles; a new column starts descending), loading skeleton, empty state
  ("Aucun épisode de sécheresse recensé…"), ongoing episode highlighted (amber row + "En cours"
  badge).

### Export CSV
- `observatoryApi.climat.exportPointUrl(lat, lon)` builds
  `/api/v1/observatory/climat/export-point.csv?lat=…&lon=…`; `PointPanel` renders it as a plain
  `<a href=… download>` — direct browser download, no client-side fetch-into-memory.

### Search field — deferred
- The repo's only search component, `components/observatory/SearchBar.tsx`, is not a
  commune/address geocoder: it's tightly coupled to `ObservatoryPage`'s station/zone/WFS state
  (matches against loaded station features + department/region/bassin/HER GeoJSON already in
  memory on that page) and has no independent lat/lon-centering API. Per the task's explicit
  instruction to keep scope tight and not build a geocoder from scratch, the search field is
  **deferred** — not built in this task.

### Types & API client
- `lib/observatory-types.ts` — `ClimatPointSeriesEntry`, `ClimatPointSeries`,
  `ClimatDroughtEpisode` (typed against the exact response shape of `GET .../point-series` and
  `GET .../point-episodes` in `api/routers/observatory_climat.py`, already implemented on this
  branch — no backend changes were needed for B2).
- `lib/observatory-api.ts` — `climat.pointSeries`, `climat.pointEpisodes`, `climat.exportPointUrl`.

### i18n
- New `climat.pointPanel.*` (title, coords, exportCsv, loadFailed, noData, noIndexData,
  precipVsNormal, precipitation, normal, indexLabel, period5y/10y/Max) and `climat.episodes.*`
  (title, start, end, duration, spiMin, deficit, empty, ongoing) keys in both `fr.json`/`en.json`.
  French labels written first per the global constraint.
